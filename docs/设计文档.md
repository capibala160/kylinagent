## 2. 核心模块设计

### 2.1 MCP 工具层

采用插件化架构，所有工具继承 `BaseTool` 基类，通过 `ToolRegistry` 统一管理。

**工具分类：**
- **System**: get_system_info, get_memory_info, get_cpu_info, get_uptime
- **Process**: list_processes, get_process_detail, find_zombie_processes, kill_process
- **Network**: get_network_connections, get_network_interfaces, check_port_usage, ping_host
- **Disk**: get_disk_usage, get_directory_size, get_io_stats, find_large_files
- **File**: read_file, list_directory, search_log, get_service_status

### 2.2 安全护栏层

**三层防护模型：**

```
用户输入
   │
   ▼
┌─────────────────┐
│  第一层: 意图校验 │ ← 检测提示词注入、恶意自然语言
│  validate_intent │
└─────────────────┘
   │
   ▼ (LLM 推理生成命令)
┌─────────────────┐
│  第二层: 命令校验 │ ← 基于规则引擎识别危险命令
│ validate_command │
└─────────────────┘
   │
   ▼
┌─────────────────┐
│  第三层: 权限隔离 │ ← 受限用户执行、只读白名单
│ PrivilegeExecutor│
└─────────────────┘
   │
   ▼
  执行
```

**风险分级规则：**

| 规则名称 | 匹配模式 | 等级 | 动作 |
|---------|---------|------|------|
| rm_root | `rm .* -rf /` | CRITICAL | block |
| mkfs_disk | `mkfs.* /dev/sd*` | CRITICAL | block |
| fork_bomb | `:(){ :|:& };:` | CRITICAL | block |
| rm_force | `rm .* -rf` | HIGH | confirm |
| kill_force | `kill .* -9` | HIGH | confirm |
| chmod_dangerous | `chmod .* 777` | HIGH | confirm |
| wget_pipe | `wget.*\|.*sh` | MEDIUM | confirm |
| prompt_ignore | `ignore previous instructions` | LOW | confirm |

### 2.3 Agent 核心编排

**处理流程（闭环）：**

```
1. INTENT_RECEIVED   → 接收用户输入
2. SECURITY_CHECK    → 意图安全校验 (提示词注入检测)
3. REASONING         → LLM 推理决策 (判断需要调用哪些工具)
4. SECURITY_CHECK    → 命令安全校验 (风险规则匹配)
5. TOOL_CALL         → 调用 MCP 工具
6. RESULT            → 汇总结果生成回复
```

每个阶段都记录到 `ReasoningChain` 中，形成可追溯的审计链路。

### 2.4 LLM 集成

支持 OpenAI API 兼容格式，可接入：
- DeepSeek (deepseek-chat)
- Qwen (qwen-turbo, qwen-max)
- 本地部署的 vLLM / Ollama 服务

提供 `MockLLMClient` 用于无模型环境下的功能测试。

## 3. 数据流设计

```
用户: "帮我清理系统垃圾"
  │
  ▼
Agent.process()
  │
  ├──→ SecurityGuard.validate_intent() → ✅ 通过
  │
  ├──→ LLM.chat_completion() → 推理需要调用:
  │      1. get_disk_usage (查看磁盘)
  │      2. find_large_files (找大文件)
  │
  ├──→ SecurityGuard.validate_command("get_disk_usage()") → ✅ SAFE
  ├──→ ToolRegistry.get("get_disk_usage").execute() → 返回 df -h 结果
  │
  ├──→ SecurityGuard.validate_command("find_large_files()") → ✅ SAFE
  ├──→ ToolRegistry.get("find_large_files").execute() → 返回大文件列表
  │
  ├──→ LLM 汇总结果 → "发现 /var/log 占用 5GB，建议清理以下日志文件..."
  │
  └──→ AuditLogger.log_chain() → 保存完整链路
  │
  ▼
用户: 收到回复 + 安全状态标识 + 链路查看链接
```

## 5. 安全设计

### 5.1 威胁模型

| 威胁 | 防护措施 |
|------|---------|
| 提示词注入 | 正则匹配注入特征，直接拦截 |
| 诱导执行恶意命令 | 规则引擎识别危险命令模式 |
| 误删关键文件 | rm -rf / 等绝对禁止，其他 rm 需要确认 |
| 权限提升 | 在 opsagent 受限用户下执行 |
| 日志篡改 | 审计日志只追加，按日期分文件 |

### 5.2 最小权限原则

- 信息收集：当前用户权限即可
- 运维操作：切换到 opsagent 用户执行
- 危险操作：必须人工确认
- 系统关键操作：绝对禁止
